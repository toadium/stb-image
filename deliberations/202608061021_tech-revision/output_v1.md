### 问题 4（轻微表述）：§3.3 options 块轮廓分写可能误解

| 项 | 内容 |
|----|------|
| **审查意见** | §3.3 将 `options("native-stub": ["wrapper.c"])` 与 `options(targets: { ... })` 分两行分写为两个独立的 `options(...)` 块。但 MoonBit 的 `moon.pkg` DSL 中，`native-stub` 与 `targets` 应在**同一个** `options(...)` 块内（见 `package-management.md:63-75` 示例）。此为轮廓描述而非完整配置，但分写可能让不熟悉 DSL 的实现者误解。 |
| **独立判断** | 合理。虽然实现者查阅 DSL 文档可自行纠正，但技术方案应避免可被误解的表述。合并为单一 options 块示意更准确。 |
| **修订措施** | 将 §3.3 配置项轮廓合并为一个 `options(...)` 块示意（含 `native-stub` 与 `targets` 两键），并注明"**单一块**同时承载 `native-stub` 与 `targets`（MoonBit `moon.pkg` DSL 要求二者在同一 `options(...)` 块内，见 `package-management.md:63-75` 示例）"。同步将 `image_test.mbt` 纳入 `targets` 块（与问题 3 修订一致）。 |
| **修订位置** | tech_v2.md §3.3 配置项轮廓（第 150-166 行） |
| **处理方式** | 修改 |
