# 审查范围界定

## 审查目标

针对 stb-image 项目当前架构进行优化审查，目标是：
- 有利于下游开发使用理解
- 项目库紧凑无歧义
- 优化模块命名和 API 命名

## 审查依据

MoonBit 官方风格指南 + 项目 AGENTS.md 约定 + 通用 API 设计原则（一致性、最小惊讶、正交性、最小化公开面），综合判断。

## 审查重点维度（全部覆盖）

| 维度 | 关注点 |
|------|--------|
| 模块命名与划分 | 八子包架构（types/pure/{codec,pixel,color,process,util}/lib/format/meta/process/util）的职责划分是否清晰无重叠，包名是否语义准确 |
| API 命名一致性 | 公开 API 命名风格（snake_case、_16/f 后缀、动词前缀等）是否统一无歧义，reexport 转发是否规范 |
| 类型系统紧凑性 | Image/Image16/ImageF 变体设计、SuperpixelResult 等结构是否紧凑，有无冗余或歧义类型 |
| 依赖关系合理性 | 子包间依赖图是否有环、层次是否清晰、有无不必要的耦合 |
| 下游可用性 | 从下游开发者视角检查 API 入口、文档注释、错误信息是否易理解易使用 |

## 背景

项目已迭代至 v3.0，包含 1056 个测试（三目标全通过）、219 个公开 API、28 个公开类型。随着功能持续增长（v2.1-v3.0 新增大量功能），架构和命名可能出现不一致或歧义，需要系统性审查以保持长期可维护性。

## 排除范围

无排除，全面审查。包括源码、测试、文档、生成文件等所有内容。

## 审查策略

由于 main 已包含 dev 全部内容，本次审查针对整个项目当前架构（而非分支差异）。按子包分轮审查：
- R1: 顶层架构 + types + reexport
- R2: pure/codec + pure/pixel
- R3: pure/color + pure/process
- R4: lib/format + lib/meta
- R5: lib/process + lib/util
- R6: 文档与下游可用性综合评估
