## 任务描述
撰写一份结构化的 stb-image 迭代计划文档，输出到工作目录下的 `iteration_plan.md`。

文档必须包含以下 7 个章节，且基于审查报告结论（不得凭空捏造方向）：

1. **计划概述**：制定日期（2026-08-08）、基于的审查报告路径、当前版本基线（v1.17.0）、总目标和阶段性愿景。
2. **迭代版本规划**：按版本号组织（v1.18、v1.19、...、v2.0、v2.1 等），每个版本含版本目标、功能项列表（功能名称、实现方式 FFI/纯 MoonBit/架构改动、涉及子包 core/process/format/meta/util、工作量评估 S/M/L/XL、优先级 高/中/低、风险点）、测试与验证要求、交付物清单、依赖关系。必须覆盖短期（下 1-2 版本）、中期（3-5 版本）、长期（v2.0+）三个时间尺度。
3. **优先级排序说明**：解释排序动机（价值/风险/成本权衡），并与审查报告中"推荐的下一步行动 Top 5"对应。
4. **风险与缓解措施**：汇总各版本主要风险，给出缓解措施。
5. **不做的事情（明确排除项）**：沿用并更新 ROADMAP.md 中的排除清单，说明排除理由。
6. **与现有 ROADMAP.md 的差异说明**：本计划与现有 ROADMAP 的主要差异点，哪些项调整了优先级、新增、移除或推迟。
7. **审阅检查清单**：列出需要用户确认的关键决策点（如 v2.0 路径 A vs B、是否纳入某功能）和优先级排序确认项。

约束：
- 计划必须基于审查报告的结论，不得凭空捏造方向。
- 每个功能项必须可执行、可验证，避免模糊描述。
- 保持 v1.0 API 冻结原则（只增不改）。
- 考虑五子包架构约束。
- 计划应覆盖短期（下 1-2 版本）、中期（3-5 版本）、长期（v2.0+）三个时间尺度。
- 产出格式应可直接作为新的 ROADMAP.md 候选内容（格式兼容）。"格式兼容"含义：产出文档采用 Markdown，章节标题层级与现有 ROADMAP.md 保持一致（一级标题为文档标题，二级标题为版本/章节分节），内容可直接替换或追加到 ROADMAP.md 中而不破坏现有锚点结构；不要求章节名称与现有 ROADMAP.md 完全相同，新增章节（如审阅检查清单）可追加在末尾。
