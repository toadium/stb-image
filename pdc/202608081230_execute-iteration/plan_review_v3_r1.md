# 计划审查报告（v3 r1）

## 审查结果
APPROVED

## 发现
- **[轻微]** 方案 A 将测试 5-6 移到新文件 `bmp_compare_test.mbt`，但测试 5-6 使用的辅助函数（`make_1x1_red_bmp_24`、`make_2x2_colors_bmp_24`）定义在 `bmp_decode_test.mbt` 第 7-17 行，计划未明确说明这些辅助函数如何在两个测试文件间共享。MoonBit 同包测试文件共享包内私有函数（语义上可行），但计划未提及此依赖关系，Doer 若遇到可见性问题需现场处理（复制辅助函数或提取到共享位置）。

- **[轻微]** 方案 A 失败转方案 B 的回退操作流程未明确。若 Doer 先执行了方案 A 的文件分离（创建 `bmp_compare_test.mbt`、修改 moon.pkg 增加 `options(targets)`），随后 `moon check` 全目标报错需转方案 B，则需回退已执行的分离操作再执行方案 B 的"移除测试 5-6"。计划未说明此回退顺序，依赖 Doer 现场判断。

- **[轻微]** 方案 B 移除对比测试（测试 5-6）后，pure 包解码正确性仅靠纯逻辑断言（测试 1-4，手工构造 BMP 数据）保证，损失与 FFI 对比的交叉验证覆盖。计划提供了补救路径（"对比验证留待后续轮次移至根包 `roundtrip_test.mbt`"），但"后续轮次"未指定具体轮次，存在对比验证空窗期。鉴于方案 B 为 fallback（仅方案 A 不可行时触发），影响可控。

- **[轻微]** 约束表述"原有 554 测试应继续通过"与方案 B"降至 552"存在字面张力。计划已通过"需在执行报告中说明"处理此差异，但表述可更精确（如"不破坏现有测试功能：方案 A 保留 554；方案 B 移除 2 个对比测试降至 552，对比验证后续补回"）。

- **[轻微]** 方案 A 的 `options(targets: { "bmp_compare_test.mbt": ["native"] })` 语法在全目标包（无 `supported_targets`）中的适用性无项目内先例（根包 `src/moon.pkg` 是 native-only 包，非全目标包）。此为 moon 标准语法，应适用，但计划未论证全目标包场景。方案 A 第 4 点已识别 `for "test"` 依赖的核心不确定性并提供 fallback，此语法问题被 fallback 机制覆盖。

## 补充说明
计划整体设计合理：正确识别关键障碍（测试对 native-only @core 的依赖）、提供优先方案 A（保留对比测试，分离到 native-only 文件）与 fallback 方案 B（移除对比测试）、明确判断标准（`moon check` 全目标是否通过）、预期产出可验证、约束（API 冻结、不破坏现有测试）明确。方案 A 的核心不确定性（全目标包能否有 native-only 的 `for "test"` 依赖）已通过 fallback 机制处理，整体计划不会卡住。所有发现均为[轻微]级别，不影响计划正确性与可行性。
